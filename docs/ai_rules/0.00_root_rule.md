# Root rule

Read this rule for every major request before doing any work.

## Where rules are

- Rules are Markdown files in `docs/ai_rules/`, named `X.XX_rule_name.md`.
- `docs/ai_rules/rule_index.json` lists every rule with its name, description and when to use it.

## Rule categories

| Number | Category |
| --- | --- |
| 0.XX | Root rules that must be read for every major request |
| 1.XX | General documentation rules, including how rules are written |
| 2.XX | Coding rules and standards |
| 3.XX | Coding documentation, such as how the codebase is structured |

## Choosing rules

1. Read `docs/ai_rules/rule_index.json`.
2. Read every rule whose `when_to_use` is `always`.
3. For each rule whose `when_to_use` is `when_applicable`, read it if its description relates to the
   task. If unsure, read it; rules are short.
4. Re-check the index when the task changes, for example from reading code to writing it.

## Following rules

- Explicit instructions from the user take priority over these rules.
- These rules add to `AGENTS.md` and the repository documentation; they do not replace them.
- If two rules conflict, follow the more specific one and tell the user about the conflict.
- To add or change a rule, follow `1.00_creating_rules`.

## Keeping rules up to date

- Prefer fitting work to the existing rules over changing them.
- If a rule is out of date, suggest a change to the user. Check that it is accurate and keeps to
  the existing standards.
- Do not suggest changes for one-off situations.
