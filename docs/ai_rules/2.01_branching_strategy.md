# Branching strategy

The repository is hosted on GitHub. Only commit, push, open pull requests or merge when the user
asks.

## Branches

- `main`: working code only. Never commit to it directly. Changes reach `main` only through pull
  requests merged on GitHub, unless the user explicitly asks to update it directly.
- `dev`: the main development branch. Rules are less strict here: testing is encouraged but not
  as strongly required.
- Change branches: make every change in its own branch, and merge it into `dev` through a pull
  request on GitHub.

## Workflow

1. Create a branch from the latest `dev` for the change.
2. Commit the change to that branch.
3. Open a pull request on GitHub to merge it into `dev`. Open pull requests frequently rather than
   collecting many changes in one.
4. Once `dev` is working, it reaches `main` through a pull request on GitHub.

`AGENTS.md` also applies: do not merge without the user's authority, and safety, public-interface
and CI-policy changes need a human's recorded review of the diff before merge.
