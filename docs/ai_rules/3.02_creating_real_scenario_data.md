# Creating real scenario data

This is the usual process for recording a drive on the car and turning it into a scenario
under `scenarios/data/`. For schema and layout rules, see `2.03_adding_and_using_test_data`.

## 1. Enable logging

Set `is_data_logging` to true under `logging` in `config/ai4r_policy.yaml`. The node reads
this at startup.

If the car does not already have that config, upload it with `scripts/car_management.sh`
(see `3.01_using_car_management_script`). Restart the policy node so the setting applies.
A restart is enough when the car already has `is_data_logging: true`. Ask before any
command that contacts the car.

## 2. Record from the start of a policy run

A new observations file and actions file are opened when the node enters publishing policy
actions. Start a new policy run for the scenario, and record from that first step. The files
are written under `logging_folder` and named with the local date and time.

## 3. Rename the pair

Replace the timestamp with one descriptive stem, and keep both suffixes. The two files must
share that stem, for example `messy_cone_test_observations.json` and
`messy_cone_test_actions.json`.

## 4. Convert the pair

Put both files in `scenarios/data/original_data`. That folder is gitignored. Run
`python -m scripts.data_converter sync` to write one scenario per pair into
`scenarios/data/real_scenarios`.

Give each scenario a short name and a description. Pipe a descriptions document into `sync`,
or pass one with `--descriptions-file`. The document is a JSON array; its fields are in
`scenarios/data/schemas/scenario_description_schema.json`. Otherwise, edit the scenario's
`name` and `description` after sync. A later sync that overwrites the file keeps the old
`description` when the new one is empty, and keeps the old `name` when the new name is only
the default derived from the input stem.

## 5. (Optional) Inspect the scenario

Open the interactive renderer with
`python -m scripts.scenario_renderer show -n <stem>`, where `<stem>` is the scenario name
without `_scenario.json`, for example `messy_cone`. Or pass `--path` to a scenario JSON file.
