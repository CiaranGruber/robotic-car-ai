# Merging conflicting rules

Use this when adding or changing a rule that overlaps existing rules, `AGENTS.md` or other
repository documentation. Always compare the new or changed guidance with related rules before
keeping both.

## When guidance conflicts

If two versions require opposite or incompatible behaviour:

1. Stop and ask the user for confirmation before writing the merge.
2. Explain why they conflict.
3. Suggest a fix (which version to keep, how to narrow scope, or how to reconcile them).

Do not silently pick a side when the behaviours disagree.

## When guidance is the same idea reworded

If both versions say the same thing in different words, keep one wording or merge them into a
single concise statement. Do not leave duplicate paragraphs.

## When both versions add valid information

If both versions contribute distinct, valid requirements:

1. Check each point against the code or documentation (see `1.00_creating_rules`).
2. Merge into one concise rule (or split topics if they do not belong together).
3. Drop anything that fails the accuracy check, and tell the user what was dropped and why.
