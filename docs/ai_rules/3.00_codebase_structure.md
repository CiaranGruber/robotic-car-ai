# Codebase structure

This is a general overview and may not list every file. Check the codebase itself before relying on
it, for example by listing the folders and reading each module's docstring.

A ROS 2 package (`ai4r_policy`) that runs a driving policy on the DREAM robotic car. Most edits are
in the `policy` package and `config/`.

## The policy package (`policy/`)

The package calculates the car's actions from its observations. It receives and returns plain
Python objects; all ROS handling stays in the node.

`policy/policy_runner.py` is the entry point, called once per policy step. It runs these stages in
order:

1. `input_output`: converts the node's raw observations into typed objects, and the chosen actions
   back into the tuple the node expects.
2. `lane_detection`: detects the lanes and road from the observations.
3. `action_policy`: chooses instructions from the observations and detected lanes.
4. `control`: converts the instructions into drive, steering and camera pan actions.

Structure:

- Each stage except `input_output` is a subpackage. Its main module holds the stage's function,
  and its other modules hold the types it produces, such as the detected lanes or the instructions.
- `policy/input_output.py` defines the observation and action types, mostly frozen dataclasses.
  Their docstrings explain each value's frame, units and when it can be `None`.

Concepts:

- Positions and IMU values use the car's body frame (`base_link`): +x forwards, +y left, +z up.
  Lidar rays stay in the lidar's own frame. Lengths and angles are in metres and radians.
- A missing or expired optional observation is `None`, never a measured zero.
- Actions are normalised values in [-1, 1]. Drive is motor effort, not speed.
- The policy runs inside the node's real-time loop, so it must never sleep, wait for input, run an
  unbounded loop or spin ROS.

## Student section of `scripts/policy_node.py`

Generally don't write code in this node unless it is to add additional observations. Policy code belongs in the
`policy` package, which the node calls. The node handles ROS input, validation, freshness, the
state machine and publishing.

- The policy calculation function (`calculate_policy_actions`) unpacks the observations into
  variables. Its `EXPLANATION OF THE OBSERVATIONS` and `EXPLANATION OF THE ACTIONS` comments are
  the authoritative meaning of each value.
- The code between the `INSERT POLICY CODE` markers, which must be kept, only converts the
  observations, calls `policy/policy_runner.py` and converts its actions back.
- The node's constructor declares and reads the policy's parameters, including general policy
  settings such as controller gains (see `2.02_adding_parameters`).

## Configuration (`config/`)

Commented YAML files; the comments document each setting, its units and its valid values.

- `ai4r_policy.yaml`: settings for this policy node, such as what triggers a policy step, which
  sensors are required, and sensor timeouts. Student parameters are added here (see
  `2.02_adding_parameters`).
- The other ROS parameter files configure DREAM components (vehicle interface, cone detector and
  IMU). DREAM owns those components.
- `camera_mount.yaml` is DREAM source configuration for the camera pose, not ROS parameters.
- Settings are read at startup, so the affected node must be restarted for a change to apply.
  Restarting the policy node does not apply another component's file; restart that component.

## Other folders

| Folder | Contents |
| --- | --- |
| `launch/` | ROS 2 launch files |
| `tests/` | Hardware-free pytest tests; policy tests go in `tests/policy/` (see `0.01_basic_codebase_rules`) |
| `tools/`, `ci/` | Verification and packaging scripts, and CI dependencies |
| `wheels/` | Vendored custom Python wheels (not uploaded to the car) |
| `docs/` | Acceptance and release records |
| `docs/ai_rules/` | These AI rules and their index |

Root files include `README.md`, `CONTRIBUTING.md` (build and test commands), `AGENTS.md`,
`requirements.txt`, and the ROS package files `package.xml` and `CMakeLists.txt`.
