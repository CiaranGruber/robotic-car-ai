# Adding parameters

Check the current code before following these steps; names and details may have changed.

Policy parameters can hold any setting the policy uses, such as a controller gain or target speed,
not only ROS settings. They are loaded as ROS parameters, so they follow ROS's declaration and
typing rules below.

## Adding a policy parameter

Follow the commented guide in the node's constructor and at the end of `config/ai4r_policy.yaml`:

1. Declare the parameter in the node's constructor with a default value and a read-only
   descriptor, because all policy settings are startup-only.
2. Add it under `ros__parameters` in `config/ai4r_policy.yaml`, with a comment explaining its
   units and range. A YAML entry alone does not declare a ROS parameter.
3. Read it in the constructor, for example into `self.speed_kp`.

- The YAML value's type must match the declared type: write `0.2` or `0.0` for a double, because
  `0` is an integer, which is a different ROS type.
- The `policy` package only receives what the node passes to it, so a parameter used there must be
  passed on from the node.
- A sensor's `sensor_timeout_s` parameter is declared automatically from its sensor name, so it
  does not need these steps (see `2.00_adding_sensors_and_observations`).

## Applying changes

- Parameters are read at startup, so restart the node for a change to apply.
- For `ai4r_policy.yaml`, restart only the policy node. A restart returns it to publishing zero
  actions; it does not enable the vehicle.
- The other ROS parameter files in `config/` belong to DREAM components. Restarting the policy node
  does not apply them; restart that component instead.
